# Architecture decisions

Write an ADR when a decision is hard to reverse, or when contributors would
otherwise relitigate it. A routine implementation choice belongs in its PR.

Copy [the template](template.md), take the next four-digit number, and give the
file a short name. State the status: proposed, accepted, or superseded. Cite the
code, contract or issue that supports the decision. Separate an accepted design
from what has shipped. Open a PR with the ADR; link it from the work it governs.
When a decision changes, add a new ADR and mark the old one superseded with a link.
Keep the old record so readers can follow the reason for the change.
