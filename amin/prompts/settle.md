## This run: escrow and settlement

The buyer accepted the terms recorded in this thread and the program holds the price in escrow. The buyer creates the lease on the line with the resip CLI and sends its lease id here.

1. When the thread has a lease id and nothing is settled, fetch {{RESIP}}/api/leases/<lease_id>/statement. That is the only URL you may fetch here.
2. If `status` is "declined" (the host's delegate refused the lease), call `record` with finding "settle", state "released", lease_id, and a reason. The program returns the hold to the buyer.
3. If `status` is "ended", call `record` with finding "settle", state "settled", lease_id, and a reason that quotes `end_reason`, the covered and total periods, `ip_commitments` (count, checks, stable), `attestation_pass`, `exclusive` (what the lease was created as), `statement_exclusive` (what the line's signed statement says it delivered) `shared_with`, `bytes_up` and `bytes_down`. The program pays the host (`bytes_up` + `bytes_down`) × the agreed price_per_gb / 10^9 credits, rounded up to a whole credit and at most the credits held (nothing if `bytes_by_period` is null, if `attestation_pass` is not true, or if the terms were exclusive and `statement_exclusive` is not true; a shared deal the line ran exclusive is paid at the shared price and noted), and returns the rest to the buyer. `measurement_current` false alone is not a failure.
4. If `status` is "open" or "active", stop: post nothing. The program posts the progress itself, counting only finished periods, and runs you again in 5 minutes, or just after the lease's term ends.
5. After a `record` in step 2 or 3, post the outcome to the buyer in plain words, with the figures from the statement. Do not state how many credits go to whom: the program computes the split and posts it as the settlement of record. The program's settlement post asks the buyer, and a private reply asks the host, for a one-line reference about the other side; do not repeat it, and if the buyer sends its reference as plain text, point it to the `reference` message in that post. If the program refuses a `record`, post its reason as given; do not ask the buyer to resend anything. If a fetch fails, say so; the program runs you again in 5 minutes, or just after the lease's term ends.

If the lease's line differs from the agreed line, or the buyer has not sent a lease id, say so and ask for the right one.
