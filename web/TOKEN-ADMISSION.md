Token-backed leases require a short-lived authorization from the dedicated accounts-service admission signer (pinned in bundled `admission-config.json`; trusted `LEASE_ADMISSION_SIGNER` deployment override supports rotation). A user-wallet signature is insufficient: the site cannot inspect the encrypted request, so it trusts the accounts service to construct it and certify its exact ciphertext, scope, wallet and current guest registration.

The site independently checks fresh guest attestation, live custody measurements and operator linkage. It reads a recent Helios head, then pins terms, balance, exposure, total claimed and token reads to that exact hash. It rejects absent/closed/released/previously claimed terms, unbacked exposure, changed bindings, stale/mixed-block/unverified chain reads and every invalid proof. The byte allowance rounds down from the entire accepted LAYC cap and rate. Token leases never debit, refund or top up staging credits; their final charge remains subject to signed guest claims.

Validation and the one append consuming nonce and reserving the wallet/terms pair are serialized per data directory. A pair is single-use even after decline/end/restart; obtain new terms for another lease. The site assumes its existing one-writer process per data directory. The lock currently serializes legacy lease submissions too, so a cold financial read can delay another new lease.

`REQUIRE_LEASE_ADMISSION=true` rejects all new legacy lease submissions. It defaults off for coordinated migration; existing leases continue. Do not enable it until the integrated kit has passed acceptance tests and affected release lanes have been notified.

The legacy sealed-envelope path has a pre-existing authority gap: the website cannot know whether an opaque staged-credit request contains a different buyer wallet/terms hash. The guest syntax-checks those sealed fields without proving wallet ownership. Merely requiring proof when a public terms hash is present does not close this gap, since an attacker can omit that public field. Proof-only admission closes new submissions at the site boundary; coexistence with arbitrary legacy envelopes needs guest remediation. Admission failure never falls back to legacy staging credit.
